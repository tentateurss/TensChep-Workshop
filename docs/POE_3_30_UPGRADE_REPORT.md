## Реализовано

1. `update` теперь скачивает и собирает данные в соседнем staging-каталоге. Рабочая папка не изменяется при ошибке скачивания или сборки.
2. Перед продвижением выполняется SQLite integrity_check и проверка непустых ключевых таблиц.
3. Версия RePoE проверяется до и после обновления. `--expect-version` отказывает несовпадающей версии, `--dry-run` не пишет данные.
4. При успешной сборке прежняя папка целиком сохраняется как `data.backup-*`; при ошибке переименования выполняется возврат рабочей папки.
5. Версия источника сохраняется в manifest и SQLite meta; планировщик показывает её в интерфейсе, старые данные обозначаются `unverified`.
6. Исправлен выбор стоимости metacraft-рецепта для класса базы в RecoveryMDP. Иначе первый рецепт с совпадающим mod id мог относиться к другому классу.
7. Снимок poe.ninja другой явно запрошенной лиги больше не предоставляет цены: используются обозначенные резервные оценки.
8. При замене SQLite удалено предварительное удаление старого файла: используется replace.
9. Добавлены регрессионные тесты выбора класса, многовалютного рецепта, защиты старой лиги, dry-run, несовпадения версии и сохранения активной БД при сбое.

Количество симуляций по умолчанию — 2000 (`POECRAFT_SIMS`). 20000 — production-ограничение числа симуляций HTTP-запроса, а не значение по умолчанию. Математические вероятности неизвестных новых механик не подменены предположениями.

## Данные и ограничения

Локальный raw manifest имеет дату 2026-10-26 и не содержит подтверждённой версии игры. Доступный RePoE всё ещё 3.29.3.6. Поэтому загрузка 3.30, сравнение настоящих экспортов, проверка новых локализаций и фактических новых рецептов не выполнены. Производные пользовательские данные сохранены.

Staging сохраняет старые файлы, которые старый механизм обновления считает допустимым оставить при ошибках необязательных загрузок. Поэтому успешное общее обновление ещё не гарантирует, что локали и Timeless соответствуют версии основного экспорта. Версия HTML RePoE — дополнительная проверка происхождения, не криптографическое доказательство единой версии всех файлов. Во время обновления сервер следует остановить. Одновременные обновления не поддерживаются. Не включён автоматический запуск полного unittest внутри обновления.

Новые частичные блокировки не поддержаны, старые допущения Aisling/Harvest/unveil/Conflict/Dominance остаются. Предупреждение версии показано в планировщике; отдельная блокировка неподтверждённых Timeless-результатов ещё не реализована. Автовыбор первой лиги API и цены при отсутствии явно выбранной лиги требуют дополнительной работы. Разделение старых кешей по версиям игры полностью не реализовано.

```text

```

После успешного обновления перезапустите сервер. Для отката остановите сервер, переименуйте текущую `data` в отдельную сохранённую папку, затем переименуйте нужную `data.backup-*` обратно в `data`. Если `POECRAFT_DATA_DIR` задан, используйте соответствующий путь. Не удаляйте текущую папку до проверки резервной копии.

До этого READY не заявляется.

## Второй этап: цены, первый проверяемый набор изменений

Исправлен автоматический переход лиг: успешно разрешённый id сохраняется в метаданных попытки даже при отказе всех категорий. Снимок предыдущей лиги исключается из расчётов. Если не удалось получить сам список лиг, новая попытка помечает выбор неподтверждённым, и цены заменяются оценками. При подтверждённой той же лиге и отказе категорий сохраняется stale-снимок с предупреждением. Старые файлы цен не удаляются.

Ключи кеша категорий дополнены SHA-256 от полного URL (включая точный id лиги и источник); перед чтением кеша проверяется точное совпадение URL. Это исключает коллизии после замены специальных символов в id и смешивание зеркал API. Добавлены локализованные объяснения отказа цен для RU/EN/DE.

Прямые запросы Python к обоим API завершились HTTP 200. На момент проверки poe.ninja вернул id Standard и Hardcore; Trade вернул Standard, Hardcore, Ruthless, Hardcore Ruthless для PC, а также варианты realm консолей. Новая лига отсутствует в этих ответах; её API id не угадывался.

Добавлены четыре теста: автоматическая смена лиги при отказе категорий, отказ определения лиги без интернета, сохранение stale для подтверждённой той же лиги, запрет повторного использования кеша другого URL. Все девять тестов `test_upgrade.py` прошли. Компиляция Python успешна. Полный прогон: см. `stage2-tests.log`.

### Точное продолжение

Этот набор изменений завершает только часть первого пункта второго этапа. Проверка снимка до первой новой попытки обновления по-прежнему опирается на сохранённые метаданные. UI пока не имеет общего переключения экономической лиги, связанного с выбором лиги оценщика; ручной выбор Trade не означает смену экономики. Эти случаи требуют следующего отдельного изменения и тестов.

Далее: (1) связать контекст цен с выбранной лигой оценщика и исключить неподтверждённый автоматический снимок при старте; (2) manifest совместимости обязательных/необязательных источников, исключение старых локалей из нового staging; (3) происхождение и совместимость Timeless с предупреждениями UI; (4) проверить официальные изменения Annulment и Chance/Alteration, не приравнивая частичные блокировки к полным; (5) read-only readiness; (6) API smoke и оставшиеся проверки. Эти пункты ещё не реализованы. Общий статус остаётся WAITING FOR GAME DATA.

Полный прогон второго этапа: **186 тестов за 52.765 секунды, OK** (`stage2-tests.log`). Ошибок unittest нет; Python пишет прогресс в stderr, что PowerShell может оформлять как NativeCommandError при перенаправлении.

## Второй этап: согласование лиги оценщика и экономики

Выбранная лига оценки теперь задаёт контекст всех чтений `Prices` внутри Item Evaluator: конвертация объявлений в chaos, ранжирование стоимости воспроизведения, справочная цена валюты и связанные поиски. Контекст хранится в ContextVar, изолирован между потоками запросов и сбрасывается в finally. Настройки окружения и пользовательский выбор не изменяются. Автоматический выбор сохраняет своё обозначение источника.

Снимок принимается только с `selection_verified: true` и источником, точно совпадающим с настроенным API poe.ninja. При несовпадении выбранной лиги цены снимка исключаются. Сопоставление выполняется с id снимка, подтверждённым механизмом resolve_league по ответу poe.ninja; таблица выдуманных соответствий Trade/ninja не создаётся. Лига, отсутствующая в экономическом источнике, получает оценки, даже если доступна на Trade. Старый неподтверждённый снимок не становится рыночным при запуске. Подтверждённый снимок той же лиги по-прежнему может использоваться как stale в пределах 24 часов.

Кеши готовой оценки и стоимости модификаторов теперь включают состояние экономических цен: результат, рассчитанный по старому снимку или fallback, не переиспользуется после изменения экономики. Ответ оценщика содержит `economy` без полного словаря цен и локализованное предупреждение в warnings/notes. UI использует существующий вывод заметок EN/RU/DE. `/api/prices` принимает необязательный параметр `league`, не меняющий серверные настройки. Новые цены по каждому запросу посетителя не скачиваются: если общий снимок не соответствует выбранной лиге, используются оценки.

Изменены `poecraft/data/ninja.py`, `poecraft/engine/prices.py`, `poecraft/engine/evaluator.py`, `poecraft/server.py`, `tests/test_upgrade.py`, `tests/test_engine.py`. Старые тестовые снимки, изображающие подтверждённые данные, дополнены метаданными источника и проверки; тесты не отключались.

Добавлены тесты первого запуска с неподтверждённым снимком, выбора другой лиги и другого источника, передачи лиги всем чтениям цен оценщика и сброса контекста. Предыдущие тесты offline, stale, смены лиги и кешей сохранены. Первый полный прогон выявил рассогласование warnings/notes после добавления предупреждения; исправлено повторным формированием notes.

Проведены компиляция Python, `prices show` и smoke локального HTTP-сервера: health 200; prices для отсутствующей лиги на EN/RU/DE — unavailable, live_count=0 с сообщением. CLI показывает резервный источник config и предупреждение об оценках. Реальные объявления Trade и браузер вручную не проверялись. Переключение выбранной лиги не скачивает отдельный снимок этой лиги: это прозрачное ограничение, а не подмена цен.

Следующая незавершённая задача: совместимость обязательных и необязательных наборов данных при обновлении — manifest происхождения/контрольных сумм/проверок, исключение несовместимых RU/DE из нового staging с английским fallback и сохранением резервной копии. Timeless и новые метакрафты в этой итерации не изменялись. Статус остаётся WAITING FOR GAME DATA.

## Staging: совместимость источников и безопасная публикация

Добавлен `data/compatibility.py`. Перед загрузкой унаследованные RU/DE raw/готовые локали и производные `*_cache.json` выводятся из активных путей в уникальный архив внутри staging. Повторная попытка не возвращает предыдущую локаль незаметно. Настройки, шаблоны и цены не перемещаются. Прежний активный набор сохраняется стандартной резервной копией при продвижении.

Перед продвижением обязательные JSON проверяются на непустое содержимое и совпадение SHA-256 с manifest загрузки. Контроль SQLite и непустых таблиц сохранён. Источник, URL, SHA-256, объявленная версия и результат проверки записываются в `compatibility.json` и SQLite meta. Сами обязательные файлы не имеют независимой версии: их совместимость честно `unverified`, а не подтверждена одной датой загрузки. Проверка index до/после загрузки остаётся дополнительной защитой, не доказательством атомарности внешнего экспорта.

Локали заново собираются существующей проверкой id и нелокализованных полей. Отсутствующий источник получает `missing`, несовместимый — `incompatible`, прошедший сравнение — `compatible`. Несовместимый готовый файл выводится из активного пути в rejected-locales, используется английский fallback. `i18n.game_data_status` возвращает статус и причину fallback. Версия локали остаётся null при отсутствии независимого подтверждения. Timeless получает происхождение из своего manifest и контрольные суммы файлов, статус `unverified` либо `missing`; набор никогда не объявляется fully_compatible. Проверка алгоритмов Timeless не выполнялась.

Исправлена выявленная тестом Windows-проблема: соединения SQLite теперь явно закрываются до переименования staging; запись метаданных явно коммитится. Проверен откат при сбое продвижения с сохранением оригинальной базы и пользовательских шаблонов.

Добавлены четыре регрессионных теста: повторный quarantine без потери настроек, отказ при неверном SHA обязательного файла, missing/incompatible локали с выводом старого файла из активного пути, сбой продвижения с восстановлением. Вместе с существующими тестами mismatch версии, dry-run и отказа загрузки — 16 целевых тестов OK. В одном предварительном полном прогоне был WinError 10053 в HTTP-тесте ограничения тела запроса; тест не отключался, итоговый прогон выполнен повторно.
