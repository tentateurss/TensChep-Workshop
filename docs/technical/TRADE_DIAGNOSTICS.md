# Диагностика нагрузки оценщика на Trade

Ответ оценщика содержит `trade_metrics`: только фиксированные имена событий и целые счётчики текущей оценки. Значения не записываются в отдельный журнал. Тексты предметов, фильтры, URL, идентификаторы объявлений, аккаунты и токены в счётчики не попадают. Счётчики параллельных оценок разделены; повторный результат из кеша получает новые счётчики.

- `search.sent`, `fetch.sent`, `reference.leagues.sent`, `reference.stats.sent` — фактические попытки HTTP-запросов, включая неудачные.
- `*.cache_hit`, `*.cache_miss` — обращения к кешам; промах не обязательно приводит к отправке запроса.
- `evaluation.cache_hit` — готовая оценка из кеша.
- `evaluation.shared_wait` — ожидание уже выполняющейся оценки с тем же ключом; поисковые запросы выполняет первый поток.
- `search.inferred_zero` — отсутствие результатов установлено по предыдущему более широкому поиску без нового HTTP-запроса.
- `search.reason.*`, `fetch.reason.*` — Unique, валюта, точный Rare, ослабленный Rare, поиск с офлайн-объявлениями или общий поиск. Дополнительный поиск альтернативных Timeless учитывается под общей причиной `evaluation`.
- `*.slot_rejected`, `*.http_error`, `*.http_429` — отказ локального лимитера и ошибки HTTP. `reference.*.failure_cache_hit` и `*.stale_hit` показывают использование защиты от повторных ошибок и устаревшего справочника.

Диагностика охватывает Trade-вызовы оценщика. Запросы poe.ninja и создание коротких ссылок вне оценщика сюда не входят. Поведение поиска, рейтинг и лимиты не изменены.

## Воспроизведение без запросов к GGG

Укажите `POECRAFT_DATA_DIR` и `POECRAFT_CONFIG_DIR` для изолированных данных, затем выполните:

```console
python -m unittest discover -s tests -p test_trade_metrics.py
python tests/trade_metrics_scenarios.py
```

Используются настоящий парсер, оценщик, кеши и лимитер; HTTP заменён контролируемыми ответами. Поиск возвращает 15 идентификаторов, поэтому успешная оценка делает два пакетных fetch. Эти числа описывают нагрузку сценария, а не качество рыночной выборки.

| Сценарий | Search | Fetch | HTTP справочников |
|---|---:|---:|---:|
| Unique, холодный кеш | 1 | 2 | 2 |
| Валюта, холодный кеш | 1 | 2 | 1 |
| Эссенция, холодный кеш | 1 | 2 | 1 |
| Rare, точное совпадение | 1 | 2 | 2 |
| Повтор любого из этих предметов | 0 | 0 | 0 |
| Rare, два ослабления до совпадения | 3 | 2 | 2 |
| Две параллельные оценки одного Unique, справочники прогреты | 1 | 2 | 0 |
| Две параллельные оценки одного Unique, ответ 429 | 1 | 0 | 0 |
| Первый ответ 429 / следующая оценка во время Retry-After | 1 / 0 | 0 / 0 | 2 / 0 |
| Covens → Standard → Covens, суммарно | 2 | 4 | 2 |

## Объединение параллельных оценок

До исправления две оценки, начавшиеся до заполнения кеша, независимо выполняли одинаковые search и fetch: лишние **1 search + 2 fetch** относительно одной оценки. Теперь они используют одну выполняющуюся задачу. Тест удерживает первый HTTP-запрос до подтверждённого входа второго потока в ожидание; случайное последовательное выполнение не удовлетворяет тесту. Последовательный повтор использует кеш. Новый поиск при смене лиги необходим; защита Retry-After предотвращает повторную отправку.

Ключ остаётся прежним: лига, текст, состояние экономики и ревизия Timeless. Разные ключи выполняются независимо. Дополнительные параметры Timeless применяются отдельно к результату каждого вызова. Подбор аналогов, бюджет поиска и лимиты GGG не изменены.

Ожидание ограничено суммой `EVAL_WAIT_BUDGET` и сетевого `TIMEOUT`. Тайм-аут или отмена ожидающего вызова не отменяет общий запрос и не запускает дублирующий. Успешное завершение, исключение или прерывание первого потока освобождает запись выполняющейся задачи; исключение передаётся ожидающим, а следующая попытка может начать новую задачу. Ответы с предупреждениями (включая 429) сохраняют прежнюю политику кеширования. Объединение действует внутри одного процесса; отдельные экземпляры приложения не разделяют задачи.

Дополнительные конкурентные проверки:

```console
python -m unittest discover -s tests -p test_evaluator_singleflight.py
```

Валюта и эссенции также обращаются к Trade даже при возможности показать котировку; без подтверждённой подходящей котировки эти запросы нельзя считать безусловно лишними.

## Быстрая котировка валюты и расходников

Для однозначно распознанных стандартных stackable-предметов свежая котировка выбранной лиги возвращается без search/fetch. Снимок проходит существующую проверку происхождения и выбора лиги; возраст дополнительно ограничен `ninja.MAX_CACHE` (30 минут). Ошибки последней загрузки, неизвестный вариант и отсутствие подходящей цены сохраняют прежний поиск. Автоматический выбор лиги следует прежним правилам Trade; явно выбранная лига не требует обращения к Trade для показа котировки.

Поле `quote` содержит источник, лигу, время снимка, ориентир за штуку, размер стопки и общий ориентир. `summary` остаётся пустым: котировка не объявляется ценой реальных объявлений. Метрика `evaluation.quote_hit` означает быстрый ответ; повторно проверяется актуальный снимок, поэтому котировка не переживает смену лиги или истечение срока свежести в кеше оценок.

Кнопка загрузки объявлений передаёт `load_listings: true` в существующий `/api/evaluate` и запускает прежний поиск с его кешем, single-flight и лимитами. Unique, Rare и Timeless не используют быстрый путь. Категории со значимыми вариантами и неизвестными свойствами не получают универсальную котировку; при поиске по категории сохраняются предупреждения об ограничениях.

## Валюта отображения

`display_rate` содержит только свежий подтверждённый курс Divine Orb из существующего Prices для лиги результата. Возраст ограничен теми же 30 минутами; интерфейс дополнительно проверяет срок действия при перерисовке. Без такого курса исходная валюта сохраняется. Для других валют пересчёт разрешён только при подтверждённой конвертации исходного объявления; оценочные курсы не используются.

В режиме «Автоматически» цена от одной Divine отображается в Divine, меньшая — в Chaos; вторая единица показывается как эквивалент. Ручной выбор влияет только на представление, не меняет сортировку, оценки, котировки за штуку/стопку и не отправляет запросы. Выбор действует в текущем окне и не изменяет пользовательские настройки на диске. Малые положительные значения показываются с порогом, а не округляются до нуля.

## Ручные фильтры Rare/Magic

Ответ существующего оценщика дополнен списком `filters`: распознанное свойство, непрозрачный стабильный идентификатор, применённые границы, доступность редактирования и причина включения/отключения. Сам адаптивный поиск и его приоритеты сохранены. Свойства без полного сопоставления с Trade нельзя включить вручную.

`manual_filters` в `/api/evaluate` — полный список `{id, enabled, min, max}` из текущего предмета. Сервер проверяет идентификаторы по заново распознанным свойствам, конечность чисел, границы и допустимые поля; произвольные Trade-запросы и stat ID клиент не передаёт. Порядок списка нормализуется. Настройки включены в ключ кеша и single-flight, поэтому разные диапазоны и лиги изолированы.

Ручной поиск использует прежний построитель запросов и лимитер. Он не снимает включённые пользователем требования: выполняется онлайн-поиск и, при отсутствии результатов, прежний поиск с офлайн-объявлениями. Диапазон гибридного мода относится к основному компоненту; остальные проверяются по наличию. При совпадающих характеристиках границы пересекаются, противоречивые диапазоны отклоняются. Отключение всех свойств явно помечается как сравнение по категории.

Изменения формы хранятся только в памяти окна и не отправляют запросов до кнопки поиска. Отдельная кнопка возвращает адаптивный режим. Предупреждение указывает, что цена предыдущего результата не относится к ещё не применённому черновику. Ручные результаты сохраняют предупреждения о точности и не объявляются подтверждённой стоимостью вставленного предмета.
# Свежесть котировок и объявлений

В снимке poe.ninja `fetched_at` сохраняет время получения тела ответа, `validated_at` — время HTTP-проверки с учётом `Age` и `Date`, `expires_at` — конец свежести источника. Чтение кеша и перезапуск не изменяют эти значения. Ответ 304 может подтвердить свежесть, но не меняет время получения тела. Пауза между запросами не продлевает TTL; просроченный снимок той же подтверждённой лиги остаётся приблизительным. Неизвестная свежесть не допускается для быстрых котировок и подтверждённого курса.

Поле Trade `indexed` отображается как время индексации объявления. Оно не подтверждает актуальность предложения и не обозначает последнее изменение цены. Отсутствующие, некорректные и будущие даты показываются как неизвестные. Формирование поисковых запросов и лимиты не меняются.
