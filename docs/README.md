## Назначение

TensChep Workshop объединяет инструменты для Path of Exile 1:

- Планировщик сравнивает способы получения предмета с заданными модификаторами, рассчитывает вероятность, ожидаемые расходы в Chaos Orb, шаги и действия после неудачи.
- Восстановление предмета сравнивает продолжение крафта уже имеющейся редкой вещи и начало заново.
- Item Evaluator ищет похожие предметы на официальном Trade и показывает объявления с ценами.
- Калькулятор Timeless Jewels определяет изменения пассивов для seed и сокета и ищет эквивалентные seed.

Сервер и вычисления написаны на Python со стандартной библиотекой. Интерфейс — обычные HTML, CSS и JavaScript без сборщика. SQLite хранит нормализованные игровые данные. Для основного запуска не требуется установка сторонних Python-пакетов. Заявленная в README минимальная версия Python — 3.10; Docker использует Python 3.12.

Приложение помогает принимать решения и формирует ссылки поиска. Оно не выполняет действия крафта в игре и не совершает покупки. Ожидаемая стоимость не является бюджетом с гарантированным результатом.

## Запуск

Команды выполняются из корня проекта.

```powershell
# Windows: подготовка данных и запуск
.\run.bat

# Ручная подготовка и запуск
python -m poecraft update
python -m poecraft serve
```

Для Linux/macOS предусмотрен `run.sh`. По умолчанию интерфейс открывается по адресу `http://127.0.0.1:8765/`.

```text
python -m poecraft serve --port 9000 --no-browser
python -m poecraft --help
python -m poecraft plan --help
```

Первичная загрузка требует интернета: основные экспорты RePoE занимают около 30 МБ; таблицы Timeless загружаются отдельно и требуют ещё примерно 35 МБ загрузки и около 70 МБ диска. Это ориентиры из существующего README, размер зависит от источников.

При готовой базе расчёты не требуют постоянного доступа к RePoE. Актуальные цены, объявления Trade и распознавание изображений зависят от внешних сервисов.

## Структура и архитектура

```text
poecraft/
  __main__.py          CLI и представление результата в терминале
  config.py            пути, переменные окружения, лимиты
  server.py            HTTP API, статика, очередь вычислений
  i18n.py              локализация интерфейса и игровых названий
  messages.py          сообщения с ключами и параметрами
  templates.py         файловые шаблоны CLI
  ocr.py               интеграция OCR.space
  ratelimit.py         ограничитель запросов по клиентам
  data/                получение и чтение данных
  engine/              вычислительная модель
  rules/mechanics.json правила и декларация поддержки механик
  locales/             en.json, ru.json, de.json
  web/                 страницы, стили и браузерная логика
config/prices.json     резервные цены
 data/                 игровые файлы, SQLite и кеши (в корне проекта)
tests/test_engine.py   набор unittest
 docker/               entrypoint и конфигурация Caddy
Dockerfile             образ приложения
 docker-compose.yml    приложение и HTTPS-прокси
```

Папка `poecraft/data` содержит код, корневая `data` — изменяемые данные. Файлы `__pycache__` — производные артефакты Python, они не являются исходным кодом.

Поток планирования: браузер или CLI → разрешение базы и целей → `ItemContext` → построение и сравнение стратегий в `Planner` → аналитика и симуляция → сообщения без привязки к языку → локализованное представление результата.

## Данные

### Подготовка игровых справочников

`data/fetch.py` получает `mods`, `base_items`, `essences`, `fossils`, `crafting_bench_options`, `item_classes` из RePoE. Исходные JSON сохраняются в `data/raw`, manifest фиксирует происхождение и контрольные суммы SHA-256. `fetch --from-dir` позволяет импортировать заранее скачанные файлы.

`data/build.py` нормализует экспорт в `data/poecraft.db`. Списки и вложенные структуры в ряде столбцов хранятся как JSON-текст. Таблицы:

| Таблица | Содержимое |
|---|---|
| `meta` | Метаданные сборки |
| `item_classes` | Классы и теги влияний |
| `bases` | Базы, класс, уровень выпадения, теги, implicits, свойства, требования |
| `mods` | Модификаторы, уровни, группы, теги, веса и численные характеристики |
| `essences` | Уровни, tier и ограничения сущностей |
| `essence_mods` | Связь сущности, класса предмета и гарантированного мода |
| `fossils` | Весовые эффекты, добавляемые и принудительные моды, ограничения |
| `bench_crafts` | Мод, мастер, tier, классы и цена верстачного крафта |
| `currencies` | Идентификаторы, названия и классы валют |

`data/repository.py` предоставляет объекты Python и кешируемый доступ к справочникам. После обновления базы работающий сервер следует перезапустить: данные уже загружены в память.

`data/eldritch.py`, `elevated.py`, `veiled.py`, `special.py` извлекают дополнительные сведения из сырых экспортов. Производные файлы `*_cache.json` позволяют не разбирать большой исходный JSON при каждом обращении и пересоздаются при изменении источника.

### Цены и Trade

`data/ninja.py` получает лиги и категории Currency, Fragment, Fossil, Resonator, Essence из poe.ninja. Обработанные цены сохраняются в `data/prices_live.json`, ответы и ETag — в `data/ninja_cache`.

Повторные запросы используют кеш минимум 5 минут; учитывается max-age с ограничением до 30 минут. При сбое снимок младше 24 часов может использоваться со статусом stale. Для отсутствующих или недоступных цен применяются оценки из `config/prices.json`; файл резервных цен не перезаписывается обновлением.

`data/trade.py` работает с официальным `pathofexile.com`: справочники характеристик и лиг, создание поиска и загрузка объявлений. Кеш списка характеристик рассчитан на неделю, списка лиг — на час. Короткая ссылка при сбое может заменяться ссылкой с запросом в URL. Не сопоставленные с Trade характеристики сообщаются пользователю, а не превращаются в выдуманные фильтры.

### Timeless

`data/timeless.py` загружает готовые таблицы Path of Building Community и дерево пассивов GGG. Файлы размещаются в `data/timeless`: manifest, index, legion, tree, conquerors и бинарные `lut_*.bin`. Авторство и лицензия исходных таблиц указаны в `data/timeless/NOTICE.txt`.

Поддержаны Glorious Vanity, Lethal Pride, Brutal Restraint, Militant Faith, Elegant Hubris и Heroic Tragedy. Эффекты читаются из таблиц, не генерируются эвристически. Эквивалентность проверяется по выбранным пассивам; для Glorious Vanity учитывается качество численных роллов. За один дополнительный запрос торговли используется до 30 эквивалентных seed.

## Расчёты

### Цели и доступность

Планировщик моделирует экипировку со слотами до трёх префиксов и трёх суффиксов: оружие, колчаны, пояса, перчатки, ботинки, нагрудники, шлемы, щиты, амулеты и кольца. Полный список находится в `SUPPORTED_ITEM_CLASSES`.

Цель задаётся семейством модификаторов и необязательным порогом. В CLI `Cold Resistance>=36` означает минимум для первого числа соответствующей характеристики. Для гибридных модов это не независимые требования ко всем строкам. `prefix:` и `suffix:` уточняют сторону. Моды одной группы конфликтуют; доступность зависит от базы, ilvl, тегов и влияний.

Порог вводится в отображаемых игровых единицах. `context.py` сопоставляет их с внутренними единицами экспорта, например для регенерации, длительности и некоторых процентов. Несовместимые цели приводят к отчёту о недостижимости.

### Стратегии и вероятности

Сравниваются варианты Chaos, сущностей, комбинаций ископаемых и резонаторов, Harvest reforge, цепочек Alteration/Regal/Exalt, завершения на верстаке и multimod. Отдельные ветви учитывают влияния, fracture, unveiled/elevated моды и Eldritch implicits. Реальная доступность определяется целью и правилами, а не самим наличием механики в этом перечне.

В `analytic.py` значимые группы отслеживаются битовыми масками. Остальные агрегируются по стороне аффикса; остаточный вес оценивается через средний вес группы с поправкой на вероятность выбора. Поэтому быстрый расчёт полуаналитический и может отличаться от точного перебора.

`Simulator` независимо выбирает моды по весам с соблюдением групп и свободных слотов. Результат включает частоту успеха и 95-процентный интервал Уилсона. Малое число успехов, расхождение методов и остановка по времени влияют на уверенность. По умолчанию настроено 2000 симуляций; старые примеры с 20000 не являются действующим значением по умолчанию.

Для простого повторения независимой попытки ожидаемое число попыток равно `1/p`, а цена повторов — цене попытки, делённой на `p`. Полный план дополнительно учитывает подготовку, верстак, значения роллов, валюту и восстановление. Для цепочек операций эта простая формула не заменяет вычислительную модель.

`RecoveryMDP` решает задачу выбора действий через итерацию значений: Exalt, Annul, metacraft с Annul/Scour/Chaos и перезапуск. Сложные варианты ограничены временем и числом состояний. Цели оптимизации: `min_cost`, `min_attempts`, `min_variance`; это выбор ранжирования реализованных вариантов, не доказательство глобального оптимума среди всех механик игры.

### Ограничения модели

Recombinators, Synthesis, Beastcrafting без данных рецептов и ряд специальных механик не поддержаны. Jewels, flasks, maps и tinctures не входят в основной планировщик экипировки; их поиск оценщиком не означает поддержку крафта.

Harvest, fracture, unveiling, некоторые влияния и специальные ископаемые используют явно помеченные допущения. Особо существенное допущение Aisling — добавление veiled-мода без удаления существующего. Для неизвестных вероятностей Orb of Conflict и Orb of Dominance могут выводиться диапазоны или схемы вместо достоверной единственной цены. Полный список причин и последствий находится в [LIMITATIONS.md](LIMITATIONS.md).

## Веб-интерфейс

| URL | Файлы | Назначение |
|---|---|---|
| `/`, `/hub` | `hub.html`, `hub.js`, `hub.css` | Каталог инструментов |
| `/craft` | `index.html`, `app.js`, `style.css` | Планирование, импорт, восстановление, шаблоны и Trade |
| `/evaluator` | `evaluator.html`, `evaluator.js`, `evaluator.css` | Оценка предметов и Timeless |

Типовой сценарий: выбрать базу и ilvl → указать влияния и цели → выбрать критерий → рассчитать → проверить стоимость, уверенность и ветви неудачи. Существующий предмет можно импортировать через Ctrl+C или Ctrl+Alt+C из игры. Парсер понимает английский, русский и немецкий текст, гибридные строки и маркеры crafted/fractured/implicit. Нераспознанные строки сопровождаются предупреждениями. Corrupted/mirrored предметы нельзя считать обычной изменяемой заготовкой.

OCR работает только при заданном `POECRAFT_OCR_SPACE_KEY`; изображение отправляется внешнему OCR.space. Распознанный текст показывается для проверки чисел. Без ключа следует использовать вставку текста.

Evaluator сначала ищет похожие предметы с фильтрами, затем при отсутствии результатов ослабляет свойства от дешёвых в воспроизведении к дорогим. Ядро наиболее дорогих модов сохраняется: до трёх, с дополнительным порогом относительно самого дорогого. Минимальные значения фильтров обычно составляют 90% значений предмета. Выводится до 15 объявлений, сначала онлайн, затем по цене в chaos. Это подбор аналогов, а не гарантированная оценка продажи. Если онлайн-аналогов не найдено с сохранённым ядром, возможен поиск офлайн-продавцов.

Компактный режим доступен через `/evaluator?compact=1`. Вынос в отдельное поверх других окон окно зависит от поддержки Document Picture-in-Picture браузером.

Язык хранится в `localStorage` под `poecraft.lang`; также сохраняются компактный режим, выбранный Timeless-сокет и браузерные шаблоны. CLI-шаблоны отдельно лежат в `data/templates.json` либо `POECRAFT_TEMPLATES`. Между этими хранилищами нет автоматической синхронизации.

### Локализация

UI-строки и объяснения находятся в `poecraft/locales/{en,ru,de}.json`. `messages.py` строит сообщения с ключами и параметрами; сервер/CLI переводят их на границе представления. Смена языка готового плана не должна менять числа или требовать нового расчёта.

Игровые названия берутся из локализованного экспорта RePoE по внутреннему id. `data/locales.py` проверяет совпадение идентификаторов и нелокализованных полей с английской сборкой. Несовместимая локаль отклоняется с сохранением предыдущего файла. Отсутствующие переводы отображаются по-английски с отметкой EN.

## HTTP API

Реализация — `poecraft/server.py`. Запросы POST передают JSON; язык обычно задаётся полем `lang`, в GET — параметром `lang`. Это внутренний API интерфейса: отдельного версионирования и OpenAPI-файла в проекте нет.

| Метод | Путь | Вход и результат |
|---|---|---|
| GET | `/api/health` | `ok`, версия, наличие файла БД, production; наличие файла не проверяет свежесть данных |
| GET | `/api/meta` | Метаданные, классы, влияния, поддержка механик и доступность OCR |
| GET | `/api/bases` | `q`, `cls`, `lang`; до 80 подходящих баз |
| GET | `/api/families` | Контекст `base`, `ilvl`, влияния; доступные семейства модов |
| GET | `/api/modsearch` | Контекст базы и `q`; поиск, включая объяснения недоступности |
| GET | `/api/locales` | Список языков |
| GET | `/api/locale` | Строки языка, английский fallback, статус игровых переводов |
| GET | `/api/prices` | Цены и статус их источников |
| GET | `/api/trade/leagues` | Лиги Trade и выбранная текущая |
| GET | `/api/timeless/tree` | Координаты и данные дерева для выбора сокета; 404 без данных |
| POST | `/api/prices/update` | Локально обновляет цены с учётом кеша; в production возвращает статус |
| POST | `/api/import` | `text`, `lang`; разобранный предмет и предупреждения |
| POST | `/api/ocr` | `image`, `lang`; OCR и разбор предмета |
| POST | `/api/plan` | `base`, `ilvl`, `influences`, `targets`, `objective`, `sims`, `lang`, `stream` |
| POST | `/api/recover` | Контекст, цели и `have` с id существующих модов; также `full_sims` |
| POST | `/api/localize` | `result_id` и `lang` либо готовый `result`; локализация без нового расчёта |
| POST | `/api/trade` | База, ilvl, влияния, цели и необязательная `league`; ссылка и предупреждения |
| POST | `/api/evaluate` | `text`, `league`, `lang`; для Timeless также `socket`, `equivalents` |

Для интеграции структуру элемента `targets` следует брать из ответа `/api/import`, результата `/api/families` и клиентского `app.js`: один свободный текст CLI не заменяет структурированный JSON API. Поле `base` в API — внутренний идентификатор базы.

При `stream: true` планирование возвращает `application/x-ndjson`: строки `{"progress": ...}`, затем `{"result": ...}` либо объект ошибки с `status`. После начала потока HTTP-статус уже 200, поэтому клиент должен проверять финальное событие. Отключение браузера не отменяет вычисление.

Ошибки: 400 — некорректные параметры; 410 — результат для локализации больше не хранится; 413 — слишком большое тело; 422 — недостижимые цели; 429 — лимит запросов; 503 — очередь/сервер занят; 500 — внутренняя ошибка. Для OCR дополнительно 501 без настройки и 502 при сбое сервиса. В памяти остаются только последние 16 результатов для повторной локализации; после перезапуска они теряются.

## CLI

| Команда | Назначение |
|---|---|
| `fetch [--url URL] [--from-dir DIR]` | Получить основные исходные JSON |
| `build` | Собрать SQLite из локальных исходников |
| `update [--url URL]` | Обновить игровые данные и производные справочники |
| `serve` | Запустить HTTP-сервер |
| `prices update` / `prices show` | Обновить цены / показать статус; поддерживают `--league` |
| `timeless update` | Обновить таблицы калькулятора |
| `bases QUERY` | Найти базы |
| `mods --base NAME [--tiers]` | Посмотреть доступные моды и id tier для `--have` |
| `plan` | Планирование или восстановление |
| `templates [--delete NAME]` | Список и удаление CLI-шаблонов |

Примеры:

```text
python -m poecraft bases regalia
python -m poecraft mods --base "Vaal Regalia" --ilvl 86 --tiers
python -m poecraft plan --base "Vaal Regalia" --ilvl 86 --target "Cold Resistance>=36" --lang ru --no-live-prices
python -m poecraft plan --paste-file item.txt --lang ru
python -m poecraft plan --paste-file item.txt --paste-as have --target "Cold Resistance>=36"
python -m poecraft plan --base "Vaal Regalia" --target "Cold Resistance>=36" --save-template "Cold armour"
python -m poecraft plan --load-template "Cold armour" --json
```

`--target` и `--influence` повторяются для нескольких значений. `--have MOD_ID` передаёт текущие моды. `--sims` задаёт число симуляций, `--quiet` отключает прогресс, `--show-all-plans` расширяет вывод. `--full-sims` включает дополнительные проверки восстановления. `--trade` строит Trade-поиск после обычного плана, `--trade-league` выбирает лигу. `--no-live-prices` в CLI отключает live-цены, используя резервные оценки.

Специальные формы целей: `fractured:TEXT>=MIN`, `TEXT (Veiled)>=MIN`, `TEXT (Elevated Elder)>=MIN`, `TEXT (Hunter)>=MIN`, `eldritch-exarch:TEXT`, `eldritch-eater:TEXT`. Нужные влияния и доступность проверяются отдельно. Полный актуальный перечень параметров конкретной команды показывает `--help`.

## Развёртывание и сопровождение

Dockerfile копирует код и резервные цены, запускает непривилегированного пользователя uid 10001, хранит изменяемые данные в `/data`. Entrypoint при отсутствии базы выполняет `update`; при отсутствии Timeless manifest отдельно пытается загрузить таблицы. Неудача этой дополнительной загрузки не блокирует запуск основного сервера.

Compose запускает приложение и Caddy. Порт приложения доступен внутри сети Compose; наружу опубликованы 80 и 443. Данные сохраняются bind mount `./data:/data`, сертификаты — в именованных томах Caddy.

```text
# Скопировать .env.example в .env, указать домен и контакт
# Настроить DNS домена и доступность портов 80/443
 docker compose up -d --build
 docker compose logs -f app

# Обновление данных после патча
 docker compose run --rm app update
 docker compose restart app
```

Существующий каталог `data` должен быть доступен на запись пользователю контейнера. Первый запуск может занять несколько минут; healthcheck имеет стартовый период 600 секунд.

В production действуют ограничения запросов по IP, общий лимит обращений к Trade, ограничение соединений и тела запроса, таймауты. Одновременно исполняется один расчёт плана; остальные ждут lock и могут получить 503. Цены обновляет фоновый поток. Сервер добавляет CSP, nosniff и запрет встраивания во frame. Доверие заголовку прокси следует включать только за контролируемым прокси. Лимиты и кеши в памяти действуют на один процесс, несколько процессов не делят их автоматически.

В коде нет пользовательских аккаунтов, общей базы пользовательских шаблонов и распределённой очереди задач. Браузерные настройки привязаны к origin и профилю браузера.

Для резервного копирования сохраняйте `data`, `config/prices.json`, файл CLI-шаблонов при отдельном пути и настройки окружения. Сырые данные и часть кешей можно загрузить заново; шаблоны пользователя следует сохранять отдельно. Перед заменой игровых данных остановите сервер или предусмотрите окно обновления, затем перезапустите его.

### Диагностика

| Симптом | Что проверить |
|---|---|
| Нет базы / запуск не удался | Выполнить `update`; проверить `POECRAFT_DATA_DIR` и права записи |
| Устаревшие цены | `/api/prices`, лигу, доступность poe.ninja и возраст снимка |
| EN рядом с названием | Наличие и совместимость локализованного экспорта; обновить данные |
| Нет подходящей стратегии | Отчёт недостижимости, ilvl, влияния, группы модов и ограничения механик |
| Долгий расчёт | Количество целей, бюджет recovery и симуляций, очередь других планов |
| HTTP 429 | `Retry-After`, общие и клиентские лимиты, заголовки Trade |
| HTTP 503 | Число соединений либо истечение ожидания вычисления |
| Timeless недоступен | `python -m poecraft timeless update`, manifest и таблицы |
| OCR недоступен | Ключ сервиса; использовать вставку текста |
| Ошибка записи в Docker | Права на bind mount `data` для uid 10001 |
| Локализация результата даёт 410 | Рассчитать заново: результат вытеснен из кеша или сервер перезапущен |

## Проверки и расширение

Основная команда проверки:

```text
python -m unittest discover -s tests
```

`tests/test_engine.py` покрывает синтетические пулы, реальные данные, достижимость, выбор стратегий, вероятности, восстановления, специальные механики, локализацию, импорт текста, поиск модов, цены, Trade, шаблоны, страницы, production-ограничения и Timeless. Проверки реальных данных зависят от подготовленных справочников; для изолированных проверок используются искусственные данные и подмены внешних ответов. Наличие теста не доказывает соответствие закрытого алгоритма игры принятому допущению.

Для нового инструмента добавьте страницу и ресурсы в `poecraft/web`, маршрут в `server.py`, карточку в `TOOLS` файла `hub.js` и ключи `hub.tool.<id>.title` / `.desc` в локали.

Для новой механики разделяйте данные источника, вычислительную модель и представление: извлечение — в `poecraft/data`, операции — в `engine`, недостающие правила — в `rules/mechanics.json`. Добавляйте объяснения через `messages.py` и локали. Неизвестные вероятности следует обозначать явно; допущения документировать в `LIMITATIONS.md`. Проверяйте конфликт групп, лимиты аффиксов, влияние ilvl и независимость чисел от языка.

Для нового языка достаточно файла локали для интерфейса; для игровых названий также требуется запись в `LOCALE_LANGUAGES`, загрузка официальных локализованных экспортов и проверка совместимости. Перевод игровых характеристик вручную нарушает принятую архитектуру сопоставления по id.

Документация отражает исследованный код. Доступность внешних API, актуальность экспортов и реальное поведение игровых механик требуют отдельной проверки при обновлении лиги.
